Explanation of the program:

This is a Python program that runs a two-player, text-based 
Tic-Tac-Toe game inside the terminal window. It uses standard
 command-line text to draw the grid and handles player inputs,
  turns, and game rules from start to finish.

The Big Picture: How the Game Works

The program sets up a continuous gameplay cycle. It draws a 3x3
 grid, asks the current player for a move, updates the grid,
  and checks if anyone won or if the game ended in a tie. It 
  repeats this sequence, switching between Player X and Player
   O, until the match concludes and asks if the players want to
    play another round.

Breakdown of Each Component


1. Visualizing the Grid (display_board)

This function takes a list of 9 items and prints them out as a 
clean, formatted 3x3 layout using vertical lines and dashes. 
When the game starts, the squares are labeled with numbers 1 
through 9 so players know where to place their marks.

2. Input Validation (get_valid_move)

This section acts as the referee for player behavior. It keeps
 asking the player for an input until they provide a safe, legal
  move. It explicitly handles three common mistakes:
• Empty Inputs: Prevents the game from breaking if a user
 presses enter without typing anything.
• Wrong Numbers: Flags inputs that are out of bounds, forcing 
numbers to stay strictly between 1 and 9.
• Stolen Squares: Checks the current board array and blocks a 
player from overwriting a cell that already contains an 'X' or 
an 'O'.

3. Win Conditions (check_win)

Every time a player makes a move, the program loops through a
 predefined blueprint of all 8 possible ways to win: three 
 horizontal rows, three vertical columns, and two diagonal paths. 
 If it finds any row where all three spots match, it signals 
 that a player has won the match.

4. Tie Breakers (check_draw)

If the win check comes up empty, this function scans every single
 square on the board. If all nine squares are filled up with 
 'X' and 'O' symbols and no empty numbers remain, it confirms 
 that the board is full and triggers a draw state.

5. Main Game Loop (play_game)

This is the master switchboard that drives the entire application.
 It initialises a clean board matrix, manages whose turn it is, 
 and swaps players from 'X' to 'O' back and forth. Once the match
  finishes, it prints out the winner, stops the active loop, and
   handles the text prompts to safely restart the board or shut
   down the application.
